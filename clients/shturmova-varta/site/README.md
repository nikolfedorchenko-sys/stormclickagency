# Сайт «Штурмова варта» – робоча верстка

ТОВ «Охоронна компанія „Штурмова варта“», Київ, +380 67 549 5710.
Зверстано за погодженим макетом `../design/concept-diia-2/` (див. його `README.md`: токени, компоненти, стани, поведінка). Візуал, структура і тексти – як у макеті; що додано понад макет – нижче.

Статичний сайт: HTML + CSS + трохи JS, без бібліотек, без збірки і без бекенду. **Нічого не задеплоєно і не опубліковано.**

## Запустити локально

```bash
cd clients/shturmova-varta/site
node tools/serve.cjs 8080          # http://localhost:8080 – як на хостингу: 404.html на відсутні адреси
# або без Node: python3 -m http.server 8080 (але тоді 404 буде стандартна)
```

`index.html` і `wizard.html` відкриваються й просто з диска (подвійний клік), крім 404.

Перевірка (потрібен Playwright: `npm i -g playwright && npx playwright install chromium`):

```bash
node tools/test-site.cjs http://localhost:8080 shots/states        # 140+ перевірок: майстер, надсилання, антиспам, маска, прокрутка, шрифт, 404, SEO
node tools/test-worker.mjs                                        # приймач заявок без мережі: поля, антиспам, Origin, Turnstile, збої Telegram
node ../../../tools/screenshot.cjs http://localhost:8080/index.html shots/index   # скриншоти 360/768/1440 + report.json
```

## Що налаштувати в `js/config.js`

| Поле | Зараз | Що вписати |
|---|---|---|
| `ENDPOINT` | порожньо | адреса приймача заявок (див. «Заявки») **[уточнити]** |
| `ENDPOINT_FORMAT` | `json` | `form`, якщо приймач чекає звичайну форму |
| `EMAIL` | порожньо | e-mail для заявок – з’явиться кнопка листа з відповідями **[уточнити]** |
| `TELEGRAM_URL`, `VIBER_URL` | порожньо | канали компанії; зникне рядок «Telegram і Viber – [уточнити]…» **[уточнити]** |
| `LINE_HOURS` | порожньо | графік телефонної лінії (меню, перший екран, стан «подзвоніть») **[уточнити]** |
| `CALLBACK_TIME` | порожньо | за скільки передзвонює менеджер («Як замовити», «Заявку надіслано») **[уточнити]** |
| `LICENSE_URL` | порожньо | посилання на ліцензію у футері; поки порожньо – там звичайний текст **[уточнити]** |
| `MIN_FILL_MS`, `TIMEOUT_MS` | 3000, 15000 | антиспам-час і тайм-аут запиту; зазвичай не чіпати. `MIN_FILL_MS` має збігатися з однойменною змінною воркера |
| `TURNSTILE_SITEKEY` | порожньо | публічний ключ Cloudflare Turnstile, якщо його увімкнуть (див. «Захист від спаму») |
| аналітика | закоментовано | GA4 / Meta Pixel – лише з ідентифікаторами від клієнта |

Ключів, токенів і паролів у `config.js` бути не може: файл бачить кожен відвідувач.

## Заявки

**Зараз `ENDPOINT` порожній, тож заявки онлайн не надсилаються.** Сайт цього не приховує: після «Надіслати заявку» клієнт бачить «Залишився один крок – подзвоніть» (нейтральний знак телефону), номер і кнопку «Подзвонити», графік лінії і всі свої відповіді, які треба назвати менеджеру (якщо задано `EMAIL` – ще кнопку листа з відповідями). Екран «Заявку надіслано» з’являється лише тоді, коли приймач відповів 2xx. Будь-яка інша відповідь, збій мережі чи тайм-аут – блок «Не вдалося надіслати заявку» з повтором і «Подзвонити», відповіді не губляться.

Рішення: **заявки йдуть у Telegram-чат менеджерів через Cloudflare Worker** (`integrations/cloudflare-worker.js`). Код готовий і перевірений без мережі (`node tools/test-worker.mjs`), але **не розгорнутий**: потрібні акаунт Cloudflare клієнта, бот і чат **[уточнити]**.

Антиспам у браузері: поле-пастка `hp_url` (поза екраном, `tabindex=-1`, `aria-hidden`, нейтральний підпис і `autocomplete="new-password"`, щоб браузер не автозаповнив її людям) і мінімальний час від відкриття майстра (`MIN_FILL_MS`). Якщо спрацювало – запит не йде, людина бачить «Залишився один крок – подзвоніть», тож хибне спрацювання не губить клієнта. Приймач перевіряє те саме ще раз.

### Що надсилає майстер – передати юристу для політики і згоди

POST на `ENDPOINT`, JSON (або форма, якщо `ENDPOINT_FORMAT: 'form'`). Усі поля – текст.

| Поле | Що це | Персональні дані? |
|---|---|---|
| `name` | ім’я, як його вписала людина | так |
| `phone` | телефон у форматі `+380XXXXXXXXX` | так |
| `address` | адреса або район об’єкта (необов’язково) | може бути |
| `service`, `service_code` | що охороняти: назва і код (`object`, `person`, `event`, `unsure`) | ні |
| `details`, `guests` | вид об’єкта / кого охороняти / вид заходу; кількість гостей | ні |
| `schedule`, `start` | графік охорони; коли почати | ні |
| `channel` | як зручніше відповісти: дзвінок, Telegram, Viber | ні |
| `search` | що людина шукала в пошуку на головній (до 80 символів) | може бути |
| `message` | усі відповіді одним текстом (для приймачів, що показують лише одне поле) | так |
| `page` | адреса сторінки майстра разом з параметрами (там можуть бути UTM-мітки) | службові |
| `referrer` | з якої сторінки перейшли на сайт | службові |
| `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content` | рекламні мітки з адреси (якщо були) | службові |
| `gclid`, `fbclid` | ідентифікатори кліку Google Ads і Meta (якщо були) | службові (ідентифікатор кліку) |
| `elapsed_ms` | скільки мілісекунд минуло від відкриття майстра (антиспам) | службові |
| `hp_url` | поле-пастка для ботів, у людей завжди порожнє | ні |
| `cf_turnstile` | токен перевірки Cloudflare Turnstile – лише якщо Turnstile увімкнено | службові |

Крім полів: приймач (Cloudflare) бачить IP-адресу і заголовки браузера; повідомлення зберігаються в Telegram (сервери поза Україною); з Turnstile Cloudflare додатково обробляє сигнали браузера для перевірки на бота. Текст згоди в майстрі зараз: «…обробить ваші ім’я, телефон, адресу (якщо вказали) та службові дані про джерело переходу, щоб зв’язатися з вами щодо заявки» + посилання на політику. **Юрист має підтвердити текст згоди і внести в політику перелік вище, Cloudflare і Telegram як обробників [уточнити].**

### Cloudflare Worker → Telegram: як розгорнути (не виконано)

1. Бот: у Telegram написати @BotFather → `/newbot` → отримати токен. Додати бота в групу менеджерів, надіслати в групу будь-яке повідомлення і взяти `chat.id` групи (напр. через `https://api.telegram.org/bot<токен>/getUpdates` у браузері; id групи від’ємний).
2. Воркер:
   ```bash
   npm i -g wrangler && wrangler login
   mkdir zayavky && cd zayavky && mkdir src
   cp <шлях-до-сайту>/integrations/cloudflare-worker.js src/index.js
   ```
   `wrangler.toml` поруч:
   ```toml
   name = "shturmova-varta-zayavky"
   main = "src/index.js"
   compatibility_date = "2026-11-01"   # дата розгортання

   [vars]
   ALLOWED_ORIGIN = "https://shturmova-varta.ua"   # справжній домен сайту [уточнити]; кілька – через кому
   MIN_FILL_MS = "3000"                             # те саме число, що MIN_FILL_MS у js/config.js
   # SPAM_NOTIFY = "0"                              # вимкнути повідомлення «підозра на спам»
   ```
3. Секрети – лише так, не в код і не в `wrangler.toml`:
   ```bash
   wrangler secret put TG_BOT_TOKEN
   wrangler secret put TG_CHAT_ID
   wrangler secret put TURNSTILE_SECRET   # лише якщо вмикаєте Turnstile
   wrangler deploy
   ```
4. Адресу воркера вписати в `ENDPOINT` у `js/config.js`. Надіслати тестову заявку з сайту, переконатися, що вона дійшла в чат; тимчасово зіпсувати `TG_CHAT_ID` і перевірити, що сайт показує «Не вдалося надіслати заявку».

Що робить воркер (подробиці – коментар на початку файлу):
- **Без налаштувань не працює**: якщо не задано `ALLOWED_ORIGIN`, `TG_BOT_TOKEN` чи `TG_CHAT_ID` – відповідає 500 і нічого не пропускає. Запити з інших сайтів (заголовок `Origin`) – 403.
- **Перевіряє дані сам**: обов’язкові ім’я, телефон `+380XXXXXXXXX`, послуга; довжини полів; розмір тіла до 16 КБ; HTML у полях екранується.
- **Антиспам**: заповнене поле-пастка `hp_url` або заповнення швидше за `MIN_FILL_MS` → **422**, а не мовчазне «успіх»: сайт покаже «Не вдалося надіслати заявку» і «Подзвонити», тож жива людина при хибному спрацюванні не загубиться. Якщо при цьому телефон схожий на справжній – у чат іде окреме повідомлення «Підозра на спам» з причиною (вимикається `SPAM_NOTIFY = "0"`).
- **Збій Telegram** (відмова чи мережа) → 502 з CORS-заголовками, сайт покаже «Не вдалося надіслати заявку» з повтором.
- У повідомлення в Telegram потрапляють відповіді, контакт, `utm_*`, `gclid`, `fbclid`, сторінка і `referrer`.

### Захист від спаму через curl

Поле-пастку і `elapsed_ms` бот, що шле запити напряму (curl), легко обійде: час рахує браузер. Справжній захист – один або обидва варіанти:

1. **Cloudflare Turnstile** (безкоштовна альтернатива капчі; у коді вже є, вимкнено). Cloudflare → Turnstile → Add widget → домен сайту, режим Managed. Публічний site key – у `TURNSTILE_SITEKEY` у `js/config.js`, секретний – `wrangler secret put TURNSTILE_SECRET`. Тоді майстер на кроці 4 підвантажує скрипт `challenges.cloudflare.com` (лише з ключем; без ключа – нічого), зазвичай невидимо, і додає токен `cf_turnstile`; воркер перевіряє його в Cloudflare і без дійсного токена відповідає 403. Turnstile – сторонній сервіс: згадати в політиці **[уточнити з юристом]**.
2. **Rate limiting у Cloudflare WAF.** Працює, якщо воркер висить на власному піддомені сайту в зоні Cloudflare (напр. `zayavky.shturmova-varta.ua`, Workers → Settings → Domains & Routes), а не на `*.workers.dev`. Security → WAF → Rate limiting rules → правило: Hostname дорівнює `zayavky.…` і Request Method дорівнює `POST` → Block, напр. 5 запитів за 10 секунд з однієї IP. Обмеження безкоштовного тарифу (кількість правил, періоди) – перевірити актуальні **[уточнити]**.

### Інші варіанти (якщо від воркера відмовляться)

- **Formspree** – без коду, заявки на пошту: у `ENDPOINT` – `https://formspree.io/f/<id>`. Поле-пастку Formspree чекає під іменем `_gotcha` – тоді перейменувати `hp_url` у `js/wizard.js`. Ліміти безкоштовного тарифу – перевірити.
- **Telegram-бот напряму з браузера – не можна**: токен бота опиниться в публічному коді.

## SEO і технічне

- `title`, `description`, `canonical`, Open Graph і Twitter на головній і в майстрі; на `privacy.html` і `404.html` – `noindex` і без `canonical` (додати `canonical` разом зі зняттям `noindex`, коли буде текст політики).
- **Домен невідомий [уточнити]**: усюди стоїть заглушка `https://shturmova-varta.example`. Коли буде домен: `python3 tools/set-domain.py https://справжній-домен.ua` (canonical, OG, schema.org, robots.txt, sitemap.xml).
- schema.org – `LocalBusiness` (у словнику schema.org окремого типу для охоронних компаній не знайшов): назва, юр. назва, телефон, Київ; зона обслуговування (`areaServed`) – Київ і в самій компанії, і в контактній точці. Вулиця, ЄДРПОУ, графік, соцмережі – не вигадані, додати, коли будуть.
- `sitemap.xml` – головна і майстер; `privacy.html` додати і зняти `noindex`, коли юрист дасть текст.
- Посилання всередині сайту – `index.html`, `wizard.html` (щоб працювало з диска); дублікати `/` і `/index.html` закриває `canonical`.

## Продуктивність

- Фото: WebP + JPEG-запас через `<picture>`, `srcset` 600/1200 w, `sizes`, `width/height`, `loading="lazy"`, `decoding="async"`. Нові фото – у `img/src/`, потім `python3 tools/optimize-images.py` (потрібен Pillow) і поправити шляхи в `index.html`.
- Шрифт Onest – локально в `fonts/` (без Google Fonts і без запитів до сторонніх серверів): змінний woff2, ваги 400–600 в одному файлі, два набори символів – кирилиця (16 КБ, `preload` на всіх сторінках) і латиниця (34 КБ, вантажиться, коли на сторінці є латиниця чи цифри); `font-display: swap`. Ліцензія SIL OFL 1.1 – `fonts/OFL.txt`, дозволяє хостити самим. Оновити файли: взяти woff2 для `cyrillic` і `latin` з CSS `https://fonts.googleapis.com/css2?family=Onest:wght@400;500;600` (запит із сучасним браузерним User-Agent).
- Інших зовнішніх ресурсів і бібліотек немає (Turnstile – лише якщо його увімкнуть). Скрипти – в кінці `body`, не блокують показ.
- OG-зображення й іконки перегенерувати: `node tools/make-icons-og.cjs && python3 tools/make-favicon-ico.py` (сервер і мережа не потрібні, шрифт – з `fonts/`). OG – окрема композиція 1200×630: градієнт першого екрана, знак «ШВ» з назвою, «Охорона об’єктів і людей онлайн», телефон; усе важливе – в центральних ~1000×520, тож не обріжеться в прев’ю соцмереж.

## Аналітика

Нічого не підключено. Місця під GA4 і Meta Pixel – закоментовані в `js/config.js`. Сайт уже викликає події (`click_call`, `click_wizard`, `wizard_step`, `lead_submit`, `generate_lead`, `lead_error`, `lead_offline`), вони запрацюють, щойно на сторінці з’явиться `gtag` чи `fbq`. Банер згоди на cookies – погодити з юристом **[уточнити]**.

## Деплой (не виконано – лише інструкція)

Підійде будь-який статичний хостинг: Cloudflare Pages, Netlify, GitHub Pages, звичайний хостинг з nginx/Apache.

1. Заповнити `js/config.js` (щонайменше `ENDPOINT`) і виконати `tools/set-domain.py`.
2. Викласти в корінь сайту: `index.html`, `wizard.html`, `privacy.html`, `404.html`, `favicon.ico`, `site.webmanifest`, `robots.txt`, `sitemap.xml`, теки `css/`, `js/`, `fonts/`, `icons/`, `img/` (**без** `img/src/`). Не викладати: `tools/`, `integrations/`, `shots/`, `README.md`.
3. Сторінка 404: Netlify і Cloudflare Pages підхоплюють `404.html` самі; nginx – `error_page 404 /404.html;`; Apache – `ErrorDocument 404 /404.html`.
4. Увімкнути HTTPS і редирект з `www`/без `www` на один варіант; кешування для `img/`, `css/`, `js/`, `fonts/` (після змін у CSS/JS – оновити кеш або додати `?v=2` до посилань).
5. Перед запуском – `seo-auditor`, а текст згоди й політику перевіряє юрист.
